Bildirim sistemi Faz 1B — minimum gerçek push sistemi.

Amaç:
Müşteriye gerçek push notification gönderebilecek minimum sistemi kuracağız.

Kapsam:
- Sadece müşteri randevu hatırlatmaları
- Randevudan 1 gün önce
- Randevudan 1 saat önce
- Randevu iptal edilirse pending hatırlatmalar iptal edilecek

Bu fazda yapılmayacaklar:
- 15 gün sonra reaktivasyon bildirimi yok
- Berber sabah özeti yok
- Berbere her yeni randevuda bildirim yok
- Deep link yok
- Büyük analytics yok
- Mesaj bildirimi yok

Teknik yapılacaklar:

1. Mobile:
- expo-notifications kur.
- Gerekirse expo-device kur.
- Login sonrası veya app açılışında notification permission iste.
- Expo push token al.
- Token’ı backend’e POST /api/push-tokens endpoint’i ile gönder.
- Platform guard ekle:
  - Web’de push token alma denemesi yapma.
  - Expo Go / development build farkı için hata durumunda app’i bozma, sadece log/uyarı ver.
- Token alınamazsa randevu sistemi çalışmaya devam etmeli.

2. DB:
push_tokens tablosu ekle:
- id
- user_id
- token unique
- platform
- created_at
- updated_at
- last_seen_at

scheduled_notifications tablosu ekle:
- id
- user_id
- appointment_id nullable
- type enum: reminder_1d, reminder_1h
- scheduled_for timestamp
- status enum: pending, sent, cancelled, failed
- title
- body
- error nullable
- created_at
- updated_at
- sent_at nullable
- cancelled_at nullable

3. Backend:
- OpenAPI’ye POST /api/push-tokens endpoint’i ekle.
- Codegen çalıştır.
- Authenticated user push token kaydedebilsin/upsert edilsin.
- Notification helper yaz:
  - Expo Push API’ye gönderim yapabilsin.
  - Şimdilik basit gönderim yeterli.
- Randevu oluşunca:
  - customerId varsa 1 gün ve 1 saat reminder kayıtları oluştur.
  - manualCustomerName/customerId=null ise bildirim oluşturma.
  - scheduled_for geçmişteyse o kaydı oluşturma.
  - İstanbul saatine göre hesapla.
- Randevu cancelled olunca:
  - appointment_id eşleşen pending scheduled_notifications kayıtlarını cancelled yap.
- No-show/completed bu fazda yeni bildirim oluşturmasın.

4. Scheduler:
- Replit Scheduled Deployment ile çalışacak şekilde bir script/entrypoint oluştur.
- Script zamanı gelen pending scheduled_notifications kayıtlarını bulsun.
- User’ın push_tokens kayıtlarına Expo Push notification göndersin.
- Başarılıysa notification status=sent, sent_at yaz.
- Başarısızsa status=failed ve error yaz.
- İlk sürüm için 5 veya 15 dakikada bir çalışacak şekilde dokümante et.
- In-process setInterval kullanma.

5. Dokümantasyon:
replit.md’ye “Bildirim Sistemi Faz 1B” bölümü ekle:
- Expo Go’da push test edilemeyeceğini
- EAS development/standalone build gerektiğini
- Replit Scheduled Deployment kurulumu gerektiğini
- Bu fazın sadece 1 gün / 1 saat müşteri hatırlatması olduğunu yaz.

Testler:
A) Mobile token register endpoint’i çalışıyor mu?
B) Randevu alınca scheduled_notifications içinde 1d/1h pending kayıtları oluşuyor mu?
C) Manuel randevu alınca bildirim kaydı oluşmuyor mu?
D) Randevu iptal edilince pending bildirimler cancelled oluyor mu?
E) Scheduler zamanı gelmiş pending bildirimi sent/failed yapıyor mu?
F) Push token yoksa scheduler crash etmiyor mu?
G) Typecheck temiz mi?
H) App push token alamazsa app crash olmuyor mu?

  - Eklenen tablolar

  - Expo/EAS için kalan manuel adımlar
