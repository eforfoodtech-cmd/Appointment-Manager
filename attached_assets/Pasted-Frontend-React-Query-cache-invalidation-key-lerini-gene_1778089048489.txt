Frontend React Query cache invalidation key’lerini generated API client query key’leriyle düzelt.

Sorun:
Bazı ekranlarda mutation sonrası manuel ve yanlış query key’ler kullanılıyor:

["getBarberSlots"]
["getUpcomingAppointments"]
["listMessages"]
bazı appointment detail remove/invalidate key’leri

Generated API client gerçek query key’leri endpoint path bazlı:

getGetBarberSlotsQueryKey(barberId, { date })
getGetUpcomingAppointmentsQueryKey()
getListMessagesQueryKey()
getListAppointmentsQueryKey()
getGetBarberDashboardQueryKey(...) varsa onu kullan
getGetAppointmentQueryKey(apptId) varsa onu kullan

İstenen düzeltmeler:

app/book/[barberId].tsx
Randevu oluşturma başarılı olunca:
upcoming appointments query doğru generated key ile invalidate edilsin.
seçilen berber/date slot query’si doğru generated key ile invalidate edilsin.
["getBarberSlots"] gibi manuel key kullanılmasın.
app/(customer)/index.tsx
Randevu iptal başarılı olunca:
getGetUpcomingAppointmentsQueryKey() ile invalidate edilsin.
manuel ["getUpcomingAppointments"] kullanılmasın.
app/(barber)/messages.tsx
Mesaj gönderme başarılı olunca:
getListMessagesQueryKey() ile invalidate edilsin.
["listMessages"] kullanılmasın.
app/appointment/[id].tsx
Appointment status değişince:
appointment detail query doğru key ile remove/invalidate edilsin.
list appointments, upcoming appointments, barber dashboard ve ilgili slot query’leri doğru key/predicate ile invalidate edilsin.
manuel yanlış key’ler kaldırılıp generated query key’ler veya endpoint path predicate kullanılsın.
app/(barber)/index.tsx
Dashboard status update sonrası:
dashboard query doğru key ile invalidate edilsin.
gerekirse /api/barbers/me/dashboard prefix veya generated dashboard key kullanılsın.
appointment status cancelled olunca slot state değiştiği için /slots query’leri de invalidate edilsin.
