7. maddeye geçiyoruz: Auth / logout canlı test.

Önce kod değiştirme. Sadece mevcut davranışı test et ve raporla.

Test edilecekler:

1. Berber login çalışıyor mu?
   - Doğru bilgilerle giriş yapınca barber paneline gidiyor mu?
   - Token AsyncStorage/local storage’a kaydediliyor mu?

2. Berber logout çalışıyor mu?
   - Logout sonrası token temizleniyor mu?
   - User bilgisi temizleniyor mu?
   - Login ekranına yönlendiriliyor mu?

3. Müşteri login çalışıyor mu?
   - Doğru bilgilerle giriş yapınca customer paneline gidiyor mu?
   - Token/user storage’a kaydediliyor mu?

4. Müşteri logout çalışıyor mu?
   - Token temizleniyor mu?
   - User bilgisi temizleniyor mu?
   - Login ekranına yönlendiriliyor mu?

5. Logout sonrası eski token kalıyor mu?
   - AsyncStorage’da TOKEN_KEY ve USER_KEY kontrol edilsin.
   - Eğer token/user kalıyorsa raporla.

6. Login olmuş kullanıcı login ekranına giderse ne oluyor?
   - Barber login olmuşken auth/login ekranına gitmeye çalışınca barber paneline yönlenmeli.
   - Customer login olmuşken auth/login ekranına gitmeye çalışınca customer paneline yönlenmeli.

7. Role guard testi:
   - Müşteri barber paneline girebiliyor mu?
   - Berber customer paneline girebiliyor mu?
   - Beklenen: girememeli, kendi paneline veya login/uygun ekrana yönlenmeli.

8. API güvenlik testi:
   - Customer token ile barber-only endpoint çağır:
     örnek: GET /api/barbers/me veya PUT /api/barbers/me/availability
     Beklenen: 403 veya uygun yetki hatası.
   - Barber token ile customer-only işlem varsa çağır:
     Beklenen: 403 veya uygun yetki hatası.

İncelenecek dosyalar:
- auth context/provider
- login ekranı
- logout butonu/profil ekranı
- app route/layout guard yapısı
- AsyncStorage TOKEN_KEY / USER_KEY kullanımı
- API auth middleware / role kontrolü

Rapor formatı:
Her test için tablo ver:
- Test
- Beklenen
- Gerçek sonuç
- Durum ✅/❌
- Kanıt / ilgili dosya veya HTTP status

Önemli:
- Kod değiştirme.
- Bug bulursan patch yapma, önce raporla.
- Demo verisini bozma.
