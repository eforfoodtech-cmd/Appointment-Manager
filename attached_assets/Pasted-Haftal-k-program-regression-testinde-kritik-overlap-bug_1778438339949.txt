Haftalık program regression testinde kritik overlap bug bulundu. Bunu şimdi patchleyelim.

Sorun:
Booked slot korunurken yeni template duration farklıysa, yeni oluşturulan free slot booked slot ile zaman aralığı olarak çakışabiliyor.

Örnek:
- Mevcut booked slot: 11:00–12:00
- Availability Pzt 30 dk yapılınca:
  - 11:00 template slotu atlanıyor
  - Ama 11:30–12:00 free slot oluşturuluyor
- Sonuç: 11:00–12:00 booked slot ile 11:30–12:00 free slot overlap oluyor.
Bu müşteri book ederse aynı zaman aralığında iki randevu oluşabilir.

Amaç:
syncDaySlots / generate slot insertion mantığını düzelt.
Yeni free slot oluşturulmadan önce sadece aynı start_time var mı diye değil, mevcut aktif/booked slotların zaman aralığıyla çakışıyor mu diye kontrol et.

İstenen davranış:
1. Booked slotlar her zaman korunmalı.
2. Yeni template slot pair'i, mevcut aktif/booked herhangi bir slot ile zaman aralığı olarak overlap ediyorsa oluşturulmamalı.
3. Sadece start_time çakışması değil, interval overlap kontrolü yapılmalı.
4. Free eski slotlar yeni template dışında kalıyorsa silinmeye devam etmeli.
5. Duplicate slot oluşmamalı.
6. Mevcut appt 74 / slot 2138 korunmalı.

Overlap kuralı:
İki aralık çakışır:
newStart < existingEnd AND newEnd > existingStart

Örnek:
- existing 11:00–12:00
- new 11:30–12:00 → overlap, oluşturma
- new 10:30–11:00 → overlap değil, oluşturulabilir
- new 12:00–12:30 → overlap değil, oluşturulabilir

Teknik öneri:
- time stringlerini minutesOfDay'e çeviren helper varsa onu kullan.
- Yoksa local helper yaz:
  timeToMinutes("11:30") = 690
- syncDaySlots içinde insertion aşamasında existing active slots listesi üzerinden range overlap kontrolü yap.
- Sadece occupiedStartTimes yeterli değil; occupiedRanges gibi bir yapı kullan.
- Büyük refactor yapma; minimal patch.

Patch sonrası regression test yap:
1. Pzt’de mevcut booked slot 11:00–12:00 varken Pzt duration=30 yap.
2. DB'de 11:30–12:00 free slot oluşmamalı.
3. Pzt slotları içinde overlap olmamalı.
4. Duplicate olmamalı.
5. Appt 74 ve slot 2138 korunmalı.
6. Restore sonrası Pzt 60dk temiz state'e dönmeli.

Rapor formatı:
- Değişen fonksiyon
- Eklenen overlap kontrolü
- Test sonucu
- Pzt 30dk testinde 11:30 slot oluştu mu/oluşmadı mı
